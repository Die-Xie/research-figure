# 科研绘图：从科学内容到可编辑图

将论文要传达的科学内容转化为清楚、准确、可继续编辑的图。默认采用以下流程，并根据用户当前请求进入相应阶段：

**阅读实现与论文 → 确定图的表达目标 → 文生图提示词 → 位图底图 → 提示词与底图迭代 → draw.io 复刻 → 局部调整与导出检查。**

图帮助读者快速理解算法或框架、关键设计与 motivation，承担建立直观认识的职责。以图形、对象变化和流程关系传递主要信息，文字负责命名、消除歧义与少量必要注释；完整推导、论证和实验解释留在论文中。足够的信息密度来自可理解的机制与关系，而不是增加文字和方框。

这是泛用工作流。项目名称、算法、示例、贡献数量、面板数量、字体、配色、画风和比例均由当前材料决定，不继承其他项目的具体设定。

## 范围与起点

- 完整绘图请求：按下述流程推进，使用已有材料和已确认版本，不反复等待无必要的确认。
- 只要分析或提示词：完成相应交付，不自动调用生图或修改源文件。
- 已有满意底图：核对科学内容后直接复刻，无需重新生成。
- 已有 `.drawio`：以最新源文件为起点，优先局部修改，不为了重新走流程而生图或重画。
- 数值曲线、统计图和实验结果图：从真实数据用绘图库生成；可作为复合图的一部分导入，不能让生成模型绘制实测数据。

只修改请求范围内的绘图材料。绘图请求不自动授权修改论文内容、提交代码、推送或发布。

## 1. 阅读科学内容，建立绘图依据

先理解论文的问题、动机、贡献、方法定义与图所在章节，再追踪对应实现的入口、主要调用关系、数据对象、条件分支和相关计算。阅读到足以解释图中关键机制的程度；不要把只读过部分文件描述为通读全部仓库。

区分论文描述、实际实现、实验观察、设计意图和未实现计划。发现冲突时定位其来源和影响，不能自行选择更有叙事效果的版本。仅在冲突会改变核心图意且无法核实时提出具体问题；其余工作可继续。

形成简短的绘图说明，复杂图可保存为伴随文件：

| 项目 | 需要明确的内容 |
| --- | --- |
| 图的职责 | 总览、机制解释、对比、流程或局部细节；面向什么读者 |
| 中心信息 | 读者看完应理解的主要结论，以及动机与方法之间的关系 |
| 内容依据 | 关键对象、操作、条件与相互关系，对应的论文段落或实现位置 |
| 表达优先级 | 哪些设计需要视觉展开，哪些基础设施只需简要呈现 |
| 输出约束 | 目标宽度或版面、语言、比例、格式、已有风格及需要保留的区域 |

只有影响设计的缺失信息才需要询问。可用合理默认值推进时说明假设，不替用户编造投稿规范或实验结论。

## 2. 写可执行的文生图提示词

阅读 [提示词设计与模板](references/prompt-template.md)。先将科学内容组织成可视化方案，再写提示词；不能只把论文段落缩短后分配给若干文字框。

1. 确定读者需要迅速看懂什么：处理什么对象，困难或约束在哪里，关键操作如何改变对象，以及产生什么结果。按图的职责取舍，不强制每张局部图覆盖全部问题。
2. 为重要机制指定具体画法：画什么对象、如何变化、如何连接、哪部分保持不变、什么条件决定分支。关键设计应有可见的内部结构，不能只用模块名代表其工作机制。
3. 将 motivation 画成与方法对应的困难或约束，例如有依据的路径阻断、结构差异或依赖关系；无需单列一大段背景文字，也不能虚构对比失败。
4. 用主结构表达核心机制，以局部细节补充理解必需的信息，把推导和完整说明留给正文。对每个区域写清“读者从图形中能看出什么”，据此分配空间。
5. 最后确定准确标签、参考风格和输出规格。明确区分给生成模型的构图说明与图中可见文字；提示词可以详细，成图文字应克制。需要标题时使用简洁标题即可，不搭配小字副标题、口号或重复解释；必要技术条件标在对应对象、操作或连线附近。

生成前做一次可视表达检查：去掉解释性长句、保留必要短标签后，主要对象、流程和关键变化是否仍可读？是否能找到动机与解法的对应？若关键区域仍只有文字框，先改可视化方案，再润色提示词。有参考图时保留其有效视觉语法与作者已接受部分，不复刻错字、重叠或科学错误。

## 3. 生成、查看并迭代位图底图

使用当前环境可用的图像生成工具；如提供图像生成 skill，遵守其调用规则。先查看编辑目标，再进行参考图编辑。不要为绕过工具缺失而自行切换付费服务或创建新的 API 调用程序。

位图提供构图与风格参考，科学内容仍以第 1 步的依据为准。实际查看生成结果，先判断图形是否让读者理解关键机制与 motivation，再检查标签、箭头、层级、密度和缩小后的可读性。若画面仍依靠长句解释，返回可视化方案，不能仅通过减字或换颜色宣告改善。

按 [设计与审阅原则](references/design-review.md) 将反馈转化为具体修改。大范围构图或风格不合适时调整提示词；底图已可作为参考时进入复刻，错字和小范围对齐可在原生绘图中修正。无需为了像素级完美而无限生成。

保留实际采用的提示词与选定底图；需要比较版本时保存候选，不让新生成结果覆盖已确认版本。

## 4. 用 draw.io 复刻为可编辑图

阅读 [draw.io 复刻与导出](references/drawio-workflow.md)。建立原生文本、形状、分组和连接关系，以可编辑 `.drawio` 为交付源文件。

复刻保留正确的信息结构、视觉层级和参考风格，并修正底图中的错误与含混。不能把整张位图作为唯一图片放进 draw.io 后声称完成可编辑复刻。必要的截图或复杂图标可以保留为图片，但其周围标签、结构和关系应可编辑。

已有作者修改时先读磁盘上的最新版本，识别保留区域；优先复用现有 ID、分组、样式和坐标，只修改本轮相关元素。不要用早期生成文件覆盖作者改动。

完成复刻后，`.drawio` 成为编辑依据，PNG、SVG、PDF 是由它生成的派生文件。

## 5. 根据问题选择迭代层级

| 反馈或问题 | 应回到的位置 |
| --- | --- |
| 机制、条件、贡献归属或科学主张有误 | 回到依据与绘图说明，再同步修正提示词或源图 |
| 整体阅读顺序、构图或风格不合适 | 重新设计布局，必要时调整提示词和底图 |
| 局部文字、配色、尺寸、对齐、连线或留白有误 | 直接修改最新 draw.io，不重新生成整图 |
| 导出裁切、缺字、字体替换或 PDF 显示异常 | 修正源文件或导出设置，再检查派生文件 |

用户的局部意见按其指定区域实施，并检查直接受影响的邻近元素；不要顺便重设计已接受区域。没有要求展示多方案时，选取有依据的方案推进。

## 6. 检查与交付

按 [设计与审阅原则](references/design-review.md) 完成科学内容和视觉检查；按 [draw.io 复刻与导出](references/drawio-workflow.md) 完成源文件与导出检查。

至少实际查看本轮交付的预览，在目标使用尺寸下检查文字和关系。XML 可解析、导出成功、画布放大后清晰，都不能代替最终尺寸下的目视检查。若本轮要求 PDF，应查看生成的 PDF；图已嵌入论文且用户要求检查排版时，再检查对应论文页面。

交付用户所需的文件，通常包括 `.drawio`、便于查看的预览以及所需的 PDF 或 SVG。简要说明主要改动、完成的检查和确实未验证的部分。工具不可用时准确交付已完成阶段，不声称已经生图、复刻、导出或验证。
