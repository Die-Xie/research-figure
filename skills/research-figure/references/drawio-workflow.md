# draw.io 复刻、局部修改与导出

目标是语义准确、视觉连贯、可继续编辑的图。位图是设计参考；开始原生复刻后，`.drawio` 是编辑依据，导出文件由源文件生成。

## 1. 识别起点并保护已有改动

- 读取磁盘上的最新源文件和最近预览，确认页面、版本及用户本轮指定区域。
- 修改已有图前保留可恢复的副本或利用已有版本机制；副本留在任务输出位置，不改变仓库或提交状态。
- 识别用户已接受或要求保留的分组、样式和区域。以最小必要范围修改，检查直接相连的元素。
- 不把整个图替换为早期模板，不因图像参考较旧而覆盖作者后来手动修改的内容。

## 2. 将底图转成可编辑对象

先建立对象清单与布局：面板边界、主要对象、文字、连接关系、分组和层级。可用相对坐标规划，再换成统一画布坐标。不要逐像素复制底图中的模糊、重复或重叠。

优先使用原生形状、文本和连接器。文本应可编辑；复用组件应能独立选择和调整。截图、实验图和复杂图标可作为必要资产，但不能用单张整图图片替代可编辑复刻。位图追踪得到的文字轮廓也不等于可编辑文本。

可以通过 draw.io 界面或直接编辑 XML 实现，取决于当前工具。若已有源文件，优先保留其结构和 ID，不无故重新生成整份 XML。

新建无压缩文件的最小结构如下；实际样式与几何由本轮设计决定：

```xml
<mxfile>
  <diagram id="page-main" name="Main">
    <mxGraphModel>
      <root>
        <mxCell id="0"/>
        <mxCell id="1" parent="0"/>
        <mxCell id="component-a" value="Component"
                vertex="1" parent="1"
                style="rounded=1;whiteSpace=wrap;html=1;">
          <mxGeometry x="40" y="40" width="160" height="70" as="geometry"/>
        </mxCell>
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

## 3. XML 与几何注意事项

- `mxCell` ID 在所属页面内唯一；`parent`、`source` 和 `target` 应指向正确对象，不能留下悬空引用。
- 分组内部通常使用相对父对象的坐标；移动或调整父组前检查子元素，避免二次偏移。
- 尽量将连接器绑定到源对象和目标对象，必要时设置连接点与途经点；独立示意线也应有明确端点。
- 背景置底、文字和必要连线可见。XML 对象存在并不表示未被遮住；检查实际绘制顺序。
- 多行文字和 HTML 标签正确转义。检查字体回退、公式、上下标及特殊符号的实际显示。
- 保留原文件的多页结构、元数据和外部资产引用。遇到压缩 diagram 内容应通过兼容编辑器或正确解码处理，不能对其盲目文本替换。

结构检查能发现重复 ID、悬空引用、异常尺寸等问题，不能证明没有重叠、科学错误或可读性问题。

## 4. 局部修改

把用户反馈映射到具体对象、文本、样式或连线；修改这些元素及必要邻接区域。保留其余内容。

例如调整一处对齐时，检查相关同类元素的基线与间距；改动连线时检查两端含义、标签和周边通道；压缩区域时优先调整间距与布局，不对全部文字作无差别缩放。只有整体构图失效时才重排大区域。

先修改 `.drawio`，再重新导出。不要只修补 PNG 或 PDF，让预览与源文件不一致。

## 5. 导出与实际检查

1. 使用当前可用的 draw.io 桌面版、CLI 或兼容渲染途径。调用前查看本机帮助或对应版本文档，不假设系统已安装特定路径或支持特定参数。
2. 按请求导出预览及 PDF、SVG 等格式。检查画布边界、裁切范围、页数和背景；清除最终导出中的临时底图、辅助框与参考图层。
3. 实际打开或渲染交付文件。检查整体与修改区域，并在拟用尺寸下查看。PDF 需要检查 PDF 的实际呈现，不能只检查来自其他渲染器的 PNG。
4. 检查文字截断、符号丢失、字体替换、遮挡、连线偏移、透明度与位图资产清晰度。导出失败或检查不完整时不要报告全部通过。
5. 确认预览与最新源文件一致。保留足够的版本信息以区分候选和已确认稿，不堆积无用临时文件。

PDF 或 SVG 容器不会自动把内嵌位图变成矢量。报告交付物时准确区分原生可编辑结构、矢量资产和截图。

## 6. 环境受限时

缺少生图工具时可以完成提示词与结构设计；缺少 draw.io 渲染器时仍可按请求产出源文件并做结构检查，但应明确未完成实际渲染验证。不要静默使用不完整的替代渲染器后声称与 draw.io 显示一致。

需要新增依赖、安装软件或调用其他服务时遵循当前会话授权与工具规则。不要把某个第三方 skill 的私有脚本或模型当成本 skill 已自带的能力。
